# Repository Conventions

- **File Paths**: Use descriptive, lowercase paths with hyphens (kebab-case).
- **Identifiers**: Use stable identifiers in markdown frontmatter.
- **History**: Use Git history for revisions. Tag releases for stable research snapshots.
- **Protocols**: Preserve original protocols and explicitly record any deviations in the experiment record.
- **Large Files**: Do not commit private data, credentials, large datasets, model checkpoints, or raw execution traces. Use external storage.
- **Dependencies**: Keep the repository lightweight. Avoid submodules unless absolutely necessary.
- **Negative Results**: Explicitly document abandoned approaches and negative findings in project and experiment records.
- **Migration**: If a project grows too large, requires independent releases, or involves extensive collaboration, migrate it to a separate repository.
